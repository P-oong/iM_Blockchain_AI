# 합성 매출 생성

목적은 매출 기반 Crisis 탐지와 이후 생존 라벨링을 연결할 수 있는 PoC 입력을 만드는 것입니다. 실제 매출이나 실제 생존예측 성능을 재현하지 않습니다. 모델 학습, 사업자별 최초 위기 선정, Y_6M/Y_12M 생성은 이 단계에 포함하지 않습니다.

## 실행

저장소 루트에서 실행합니다. Python 3.10 이상, 표준 라이브러리만 사용합니다.

```powershell
python src/data/generate_synthetic_sales.py
python src/data/generate_synthetic_sales.py --start-quarter 2015Q1 --end-quarter 2025Q4 --seed 42 --shock-probability 0.08
python -B -m unittest discover -s tests -v
```

- `--input`: 원본 CSV 경로. 생략 시 `data/raw/`에 CSV가 정확히 하나 있어야 합니다.
- `--output`: 생성 CSV 경로. 기본값 `data/synthetic/synthetic_dip_sales.csv`. 기존 출력은 재실행 시 갱신합니다. 원본 파일과 `data/raw/`에는 출력할 수 없습니다.
- `--encoding`: 입력 인코딩. 기본값 `utf-8-sig`; 필요하면 `cp949`로 지정합니다.
- `--shock-probability`: 각 지역·업종·분기의 충격 시작 확률. 위기 표본의 비율을 의미하지 않습니다.
- `--use-competition`: 이전 연도 경쟁지표를 사용하는 실험 옵션. 현재 원본에는 구를 구분하지 않은 집계 문제가 있어 기본적으로 끄며, 서로 다른 구의 동명이 겹치면 실행을 거부합니다.

## 입출력 계약

기본 입력은 `구`, `읍면동`, `업종`입니다. `기준연도`가 있으면 종료연도보다 늦은 행은 제외합니다. 연도 없는 지역·업종 목록도 입력할 수 있습니다. 사업체별 반복 행은 지역·업종 조합으로 중복 제거하고 원본은 수정하지 않습니다.

출력 CSV는 UTF-8 BOM을 사용하며 아래 6개 열만 포함합니다. 사용자가 제공한 DIP 예시를 따른 **잠정 스키마**로, 실제 DIP 명세와의 일치는 아직 검증하지 않았습니다.

| 열 | 의미 |
| --- | --- |
| 기준분기 | `2015Q1` 형태 |
| 구 | 원본 구·군 명칭 |
| 읍면동 | 형식 검사를 통과한 원본 지역 문자열; 행정동 미확인 |
| 업종 | 원본 업종 명칭 |
| 매출액 | 해당 지역·업종의 합성 분기 매출, 원 단위 양의 정수 |
| 이용건수 | 합성 매출액과 가정한 객단가로 산출한 양의 정수 |

고유키는 `기준분기 + 구 + 읍면동 + 업종`입니다. 같은 동명이라도 구가 다르면 별도 시장입니다. 선정된 모든 조합에 모든 분기를 생성하는 고정 패널이므로, 특정 분기 사업체 존재 여부는 이후 실제 사업자 모집단에서 판단해야 합니다.

## 생성 원리

`매출 = 업종 기본규모 × 지역규모 × 시장규모 × 계절성 × 추세 × 업종·도시 경기순환 × 경쟁효과 × 지역충격 × 잡음`

- 음식점·휴게음식점·미용·축산 등의 기본규모와 계절성을 구분합니다. 나머지 업종은 시드로 고정한 기본값을 사용합니다.
- 지역 규모와 업종별 성장률, 도시·업종 경기순환은 가정값입니다. 실제 통계로 추정한 값이 아닙니다.
- 2016Q1부터 독립적인 지역 충격을 추첨합니다. 매출 수준을 28~52% 낮추고 2~4분기 유지한 뒤 2~5분기에 걸쳐 회복시킵니다. 겹친 충격은 더 강한 충격을 적용합니다.
- 분기 간 상관이 있는 작은 잡음을 넣고, 매출과 업종별 객단가에서 이용건수를 계산합니다.
- 기본 경쟁효과는 `1`입니다. 옵션 활성화 시 전년도 신규진입률과 전년/전전년 동일업종 수 증가만 하방압력으로 사용합니다. 과거 지표가 없으면 중립 처리하며 미래 값으로 채우지 않습니다.
- 시드와 지역·업종·시점별 난수 흐름을 고정합니다. 입력 순서, 중복 행, 폐업정보 변경이 매출을 바꾸지 않습니다. 같은 지역 목록에서 생성기간을 늘려도 기존 분기의 매출은 유지됩니다.

원본의 폐업일, 폐업여부, 폐업까지 업력, 생존 라벨은 사용하지 않습니다. 합성 충격을 실제 폐업 결과에 맞춰 배치하거나 위기 비율을 맞추기 위해 라벨을 참조하지 않습니다.

## Crisis 점검

생성 후 매출의 전년 동분기 변화율을 계산합니다. 비교 업종 성장률은 **포함된 모든 지역의 매출 합계를 먼저 구한 뒤 전년 대비 증감률을 계산**합니다. 지역별 성장률의 단순평균을 사용하지 않습니다.

`YoY <= -0.20 AND (YoY - 업종 합계 YoY) <= -0.10`

조건을 만족하는 지역·업종·분기 수를 메타데이터에 기록합니다. 2015년처럼 전년 분기가 없는 행은 평가에서 제외합니다. 이 결과는 생성 점검용이며, Crisis는 종속변수가 아닙니다. 실제 사업자 라벨링 시 관측기간 부족을 생존으로 처리하면 안 됩니다.

## 현재 원본에서 확인한 한계

- `읍면동`에 `100동`, `상가동`, `관리동` 등의 추출 오류가 있습니다. 결측·명백한 건물 표기를 제외하고 건수를 기록하지만, 형식 검사만으로 법정동/행정동 또는 모든 오류를 구별할 수 없습니다. 별도 주소·행정동 매핑이 필요합니다.
- 경쟁지표 `동_동일업종수`는 구를 제외한 `기준연도 × 읍면동 × 업종`으로 집계되어 동명이 같은 서로 다른 구가 합쳐져 있습니다. 실제 전처리 단계에서 구를 포함해 다시 산출해야 합니다.
- 기본 2025Q4 생성에서는 2026년 행을 사용하지 않습니다. 원본 `기준일자=2026-12-31`은 연말 스냅샷 표기이므로 실제 관측 종료일로 간주할 수 없습니다.
- 군위군 등을 포함한 원본 지역 목록을 과거에도 동일하게 적용합니다. 역사적 행정구역 변경을 재현하지 않습니다. 업종 비교치는 이 목록 내 합성 매출 합계이며, 공식 대구 전체 매출이 아닙니다.
- 합성 생성은 지역·업종 목록을 과거 분기에도 적용한 시뮬레이션입니다. 과거에 실제 관측 가능했던 모집단·행정구역을 복원한 데이터로 해석하면 안 됩니다.
